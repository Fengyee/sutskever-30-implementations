## 核心概念

## Part I: Lost in the Middle — 长上下文中的位置偏差

### 现象发现

Liu et al. (2023) 发现了大型语言模型在处理长上下文时的一个关键弱点：当相关信息放置在输入上下文的**不同位置**时，模型的性能呈现一条 **U 形曲线**：

- **开头位置**的信息：模型利用得很好
- **结尾位置**的信息：模型利用得也不错
- **中间位置**的信息：模型表现明显下降

这意味着，即使模型声称支持很长的上下文窗口（如 4K、8K、32K tokens），它实际上并不能均匀地利用所有位置的信息。

### 首因效应与近因效应

这一现象与认知心理学中的两个经典效应密切相关：

**首因效应 (Primacy Effect)**：人们倾向于更好地记住列表开头的内容。在 LLM 中，开头的 token 在所有后续注意力计算中都参与了，因此获得了更多的"曝光"。

**近因效应 (Recency Effect)**：人们倾向于更好地记住列表末尾的内容。在 LLM 中，靠近生成位置的 token 在注意力窗口中更"新鲜"，权重更高。

中间位置的信息两边都不靠——既不是最早看到的，也不是最近看到的——因此最容易被忽略。

### 为什么 LLM 对中间位置信息处理较差

**注意力分布的不均匀性**：

自注意力机制中，注意力权重通过 softmax 归一化。在长序列中：

$$\alpha_{ij} = \frac{\exp(q_i^\top k_j / \sqrt{d})}{\sum_{l=1}^{n} \exp(q_i^\top k_l / \sqrt{d})}$$

当序列很长时，注意力被稀释，模型倾向于关注少数"显著"的位置——通常是开头和结尾。

**位置编码的影响**：

旋转位置编码 (RoPE) 等相对位置编码使得距离较近的 token 对之间有更强的位置信号。中间位置的 token 与生成位置距离较远，位置信号衰减。

**训练数据的偏差**：

模型在训练时看到的大多数任务中，关键信息往往出现在文本的开头或结尾（如文章摘要、对话的最后一条消息），这导致了位置偏差的强化。

### 实验设计

Liu et al. 的实验设计简洁而有力：

1. 给模型提供 $n$ 个文档（如 10 个或 20 个）
2. 其中只有 1 个文档包含问题的答案
3. 改变这个关键文档在输入中的位置（开头、中间、结尾）
4. 测量模型的回答准确率

结果一致显示 U 形曲线，且随着上下文长度增加，中间位置的性能下降更严重。

### 长上下文优化策略

针对 Lost in the Middle 问题，研究者提出了多种缓解策略：

1. **重新排序**：将最相关的文档放在输入的开头和结尾
2. **分块处理**：将长文本分成多个块，分别处理后合并
3. **注意力机制改进**：如 Longformer 的局部+全局注意力、StreamingLLM 的注意力汇聚
4. **位置编码改进**：如 ALiBi、YaRN 等能更好处理长距离依赖的编码方式
5. **训练策略**：在训练时使用更长的上下文，并刻意将关键信息放在不同位置

## Part II: 多 Token 预测 (Multi-Token Prediction)

### 标准自回归预测的局限

传统语言模型的训练目标是**逐 token 预测**：

$$\mathcal{L}_{\text{next-token}} = -\sum_{t=1}^{T} \log p(x_t | x_{<t})$$

每次只预测下一个 token。这种方式存在以下问题：

1. **训练信号稀疏**：每个位置只提供一个 token 的监督信号
2. **缺乏远见**：模型可能学到局部最优但全局次优的策略（如总是生成安全但无聊的 token）
3. **推理速度受限**：每次只生成一个 token，自回归解码很慢

### 多 Token 预测的核心思想

Gloeckle et al. (2024) 提出同时预测未来 $n$ 个 token：

$$\mathcal{L}_{\text{multi-token}} = -\sum_{t=1}^{T} \sum_{k=1}^{n} \log p(x_{t+k} | x_{\leq t})$$

模型在每个位置不仅预测 $x_{t+1}$，还预测 $x_{t+2}, x_{t+3}, \ldots, x_{t+n}$。

### 架构设计

多 Token 预测的架构在标准 Transformer 基础上做了关键修改：

**共享主干 (Shared Backbone)**：所有预测头共享同一个 Transformer 主干网络，它负责处理输入序列并产生上下文表示。

**多个预测头 (Prediction Heads)**：在主干之上，有 $n$ 个独立的预测头（通常是简单的线性层或小型 Transformer 层），每个头负责预测一个特定的未来位置：

- 头 1：预测 $x_{t+1}$（与标准自回归相同）
- 头 2：预测 $x_{t+2}$
- ...
- 头 $n$：预测 $x_{t+n}$

$$\hat{x}_{t+k} = \text{Head}_k(\text{Backbone}(x_{\leq t}))$$

### 单 Token vs 多 Token 预测的效率对比

| 方面 | 单 Token | 多 Token ($n$=4) |
|------|----------|-----------------|
| 每个位置的训练信号 | 1 个 | 4 个 |
| 推理速度潜力 | 基线 | 最多 4x（speculative decoding） |
| 额外参数 | 无 | $n-1$ 个预测头（较小） |
| 训练 FLOPs | 基线 | 约增加 10-20% |
| 模型能力 | 局部优化 | 鼓励更长期的规划 |

### 为什么多 Token 预测能提升模型质量

**更丰富的训练信号**：每个位置提供 $n$ 倍的梯度信号，模型学到的表示需要同时支持多个预测任务，促使学习更丰富的特征。

**长期规划能力**：预测 $x_{t+3}$ 需要理解更长的语义依赖。这迫使模型的内部表示编码更多的"未来信息"，而不仅仅是下一个 token 的局部统计。

**与 speculative decoding 的协同**：训练时学到的多个预测头可以在推理时用于并行投机解码 (speculative decoding)，直接提升推理速度。

### 训练目标的数学形式

$$\mathcal{L} = \sum_{k=1}^{n} \lambda_k \cdot \mathcal{L}_k$$

其中：

$$\mathcal{L}_k = -\frac{1}{T} \sum_{t=1}^{T-k} \log p_k(x_{t+k} | x_{\leq t})$$

$\lambda_k$ 是每个预测头的损失权重。通常 $\lambda_1 \geq \lambda_2 \geq \ldots \geq \lambda_n$，因为越近的预测越重要。

---

## 关键公式

### 注意力权重分布（Lost in the Middle 相关）

位置 $j$ 对位置 $i$ 的注意力权重：

$$\alpha_{ij} = \text{softmax}\left(\frac{Q_i K_j^\top}{\sqrt{d_k}}\right)$$

在长上下文中，有效注意力倾向于集中在少数位置，导致中间位置的信息被忽略。

信息利用度随位置变化呈 U 形曲线：

$$\text{Performance}(pos) \approx a \cdot (pos - \frac{L}{2})^2 + b$$

其中 $L$ 是上下文长度，$pos$ 是关键信息的位置。

### 多 Token 预测损失

$$\mathcal{L}_{\text{MTP}} = -\frac{1}{T} \sum_{t=1}^{T} \sum_{k=1}^{n} \lambda_k \log p_{\theta_k}(x_{t+k} | h_t)$$

其中 $h_t = \text{Backbone}_\phi(x_{\leq t})$ 是共享主干的输出，$\theta_k$ 是第 $k$ 个预测头的参数。

### 训练效率比较

单 Token 预测的每步梯度信息量：$O(T)$

多 Token 预测的每步梯度信息量：$O(n \cdot T)$

额外计算开销（预测头部分）：$O(n \cdot d \cdot V)$，其中 $d$ 是隐藏维度，$V$ 是词表大小。

## 直觉理解

### Lost in the Middle 的书架类比

想象一个很长的书架，你需要找到某本特定的书：

- **最左边**的几本书很容易找到（因为你从左边开始看）
- **最右边**的几本书也容易找到（因为你会注意到书架的尽头）
- **中间**某处的书最难找到（视觉上不突出，容易被忽略）

LLM 处理长上下文时也有类似的"注意力盲区"。这不是模型不能看到中间的信息——它在技术上可以——而是在实际的注意力分配中，中间位置的信息不容易脱颖而出。

### 多 Token 预测的下棋类比

单 Token 预测就像下棋时只想一步——选择当前看起来最好的走法。

多 Token 预测就像同时想 4 步——选择当前走法时，考虑这步会如何影响后面 3 步。这自然会导致更好的"战略眼光"。

国际象棋高手和新手的区别，正是在于前者能看到更远的未来局面。多 Token 预测用类似的方式训练语言模型"看得更远"。

### 两个主题的联系

Lost in the Middle 和多 Token 预测看似不相关，但它们共同揭示了自回归语言模型的两个根本局限：

1. **空间维度**：模型不能均匀地利用上下文中所有位置的信息（Lost in the Middle）
2. **时间维度**：模型的预测可能过于"近视"，只关注下一个 token（单 Token 预测的局限）

两者都指向一个更深层的问题：**如何让模型更好地建模长距离依赖**。

## 与其他论文的关联

- **RAG / DPR**：Lost in the Middle 直接影响 RAG 的效果——检索到的多个文档在输入中的排列顺序会显著影响生成质量
- **Attention Is All You Need**：注意力机制是 Lost in the Middle 问题的根源，也是多 Token 预测的基础架构
- **Scaling Laws**：多 Token 预测可以看作一种提升训练效率的方法，与缩放定律中的计算效率优化相关
- **GPipe**：训练多头预测模型可能需要更多计算资源，流水线并行等分布式训练技术是支撑
