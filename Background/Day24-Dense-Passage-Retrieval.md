## 核心概念

### 开放域问答的检索问题

开放域问答 (Open-Domain QA) 需要从海量文档中找到包含答案的段落。传统方法使用基于词频的**稀疏检索**（如 BM25），但这些方法只能捕捉词汇层面的匹配，无法理解语义相似性。

例如，问题"谁发明了电话？"和段落"贝尔于1876年获得了电话的专利"之间没有共享的关键词"发明"，但它们语义上高度相关。

DPR 的核心贡献是证明了：**简单的双编码器架构，配合适当的训练策略，可以显著超越 BM25 等稀疏检索方法。**

### 双编码器架构 (Bi-Encoder)

DPR 使用两个独立的 BERT 编码器：

**查询编码器 $E_Q$**：将自然语言问题编码为稠密向量

$$\mathbf{q} = E_Q(\text{question}) \in \mathbb{R}^d$$

**段落编码器 $E_P$**：将文本段落编码为稠密向量

$$\mathbf{p} = E_P(\text{passage}) \in \mathbb{R}^d$$

两个编码器的输出都取 `[CLS]` token 的隐藏状态作为整个序列的表示。

**相似度计算**：简单的内积（点积）

$$\text{sim}(q, p) = \mathbf{q}^\top \mathbf{p} = E_Q(q)^\top E_P(p)$$

### 为什么用双编码器而非交叉编码器

**交叉编码器** (Cross-Encoder) 将问题和段落拼接后输入单个 BERT，能捕捉更细粒度的交互，但检索时需要对每个候选段落都做一次前向传播——当候选库有数百万段落时，这完全不可行。

**双编码器**的优势：段落向量可以**预先计算并索引**。检索时只需编码查询，然后在索引中进行向量搜索，速度快几个数量级。

### 训练策略

**训练目标**：给定一个问题 $q_i$ 和其正例段落 $p_i^+$，以及一组负例段落 $\{p_{i,j}^-\}$，最大化正例的相似度，最小化负例的相似度。

使用对比学习的 softmax 交叉熵损失：

$$\mathcal{L}(q_i, p_i^+, p_{i,1}^-, \ldots, p_{i,n}^-) = -\log \frac{e^{\text{sim}(q_i, p_i^+)}}{e^{\text{sim}(q_i, p_i^+)} + \sum_{j=1}^{n} e^{\text{sim}(q_i, p_{i,j}^-)}}$$

### In-Batch Negatives: 高效的负例策略

DPR 的一个关键创新是 **in-batch negatives**：

在一个 batch 中，有 $B$ 个 $(q_i, p_i^+)$ 对。对于每个问题 $q_i$，将 batch 中**其他所有问题的正例段落**作为负例。

这意味着：
- 每个 batch 提供 $B-1$ 个负例（无需额外计算）
- 段落编码只需计算一次，被所有问题共享
- batch size 为 $B$ 时，有效负例数为 $B-1$

**为什么有效？** 因为随机选取的段落大概率不包含某个特定问题的答案，所以其他问题的正例段落对当前问题来说是有效的负例。

### 困难负例 (Hard Negatives)

除了 in-batch negatives，DPR 还使用了**困难负例**：

- 用 BM25 检索出与问题词汇相似但不包含答案的段落
- 这些段落是"看起来相关但实际不相关"的例子
- 迫使模型学习更深层的语义匹配

实验表明，加入 BM25 困难负例使检索准确率显著提升。

### 最大内积搜索 (MIPS) 与 FAISS

训练完成后，需要在数百万段落中快速找到与查询最相似的段落。这是一个**最大内积搜索** (Maximum Inner Product Search, MIPS) 问题：

$$p^* = \arg\max_{p \in \mathcal{C}} \mathbf{q}^\top \mathbf{p}$$

精确搜索的时间复杂度为 $O(|\mathcal{C}| \cdot d)$，对于百万级语料库不可接受。

**FAISS** (Facebook AI Similarity Search) 提供了高效的近似最近邻 (ANN) 搜索：

1. **IVF (Inverted File Index)**：将向量空间划分为若干 Voronoi 单元，检索时只搜索最近的几个单元
2. **PQ (Product Quantization)**：将高维向量压缩为紧凑的编码，减少内存和计算
3. **HNSW (Hierarchical Navigable Small World)**：基于图的近似最近邻方法

DPR 使用 FAISS 的 HNSW + IVF + PQ 组合索引，能够在毫秒级完成对 2100 万段落的检索。

### 稠密检索 vs 稀疏检索

| 特性 | 稀疏检索 (BM25) | 稠密检索 (DPR) |
|------|-----------------|----------------|
| 表示 | 高维稀疏向量（词频） | 低维稠密向量（语义） |
| 匹配方式 | 精确词汇匹配 | 语义相似度 |
| 同义词处理 | 差（需要手动扩展） | 好（自动学习语义） |
| 精确匹配 | 强 | 可能遗漏精确关键词 |
| 零样本 | 不需要训练数据 | 需要标注数据 |
| 更新 | 即时（词频统计） | 需要重新编码 |
| 检索速度 | 快（倒排索引） | 需要 ANN 索引 |

**实践建议**：DPR 在语义匹配上更强，BM25 在精确匹配上更可靠。两者可以互补——许多实际系统使用混合检索（hybrid retrieval），结合两种方法的优势。

## 关键公式

### 相似度函数

$$\text{sim}(q, p) = E_Q(q)^\top E_P(p)$$

使用点积而非余弦相似度，因为点积在 MIPS 框架下更自然，且实验效果更好。

### 对比学习损失

$$\mathcal{L} = -\log \frac{e^{\text{sim}(q_i, p_i^+)}}{e^{\text{sim}(q_i, p_i^+)} + \sum_{j=1}^{n} e^{\text{sim}(q_i, p_{i,j}^-)}}$$

这等价于 $(n+1)$ 类分类问题的交叉熵损失，正例为第 0 类。

### In-Batch Negatives 的相似度矩阵

对于 batch size 为 $B$ 的训练：

$$S_{ij} = E_Q(q_i)^\top E_P(p_j), \quad i,j \in \{1, \ldots, B\}$$

$S$ 是一个 $B \times B$ 的矩阵，对角线元素 $S_{ii}$ 对应正例对。

损失函数变为：

$$\mathcal{L} = -\frac{1}{B} \sum_{i=1}^{B} \log \frac{e^{S_{ii}}}{\sum_{j=1}^{B} e^{S_{ij}}}$$

### BM25 基线

稀疏检索的经典方法 BM25 的得分函数：

$$\text{BM25}(q, p) = \sum_{t \in q} \text{IDF}(t) \cdot \frac{f(t, p) \cdot (k_1 + 1)}{f(t, p) + k_1 \cdot (1 - b + b \cdot \frac{|p|}{avgdl})}$$

其中 $f(t, p)$ 是词 $t$ 在段落 $p$ 中的频率，$\text{IDF}(t)$ 是逆文档频率。

## 直觉理解

### 语义空间中的匹配

想象一个图书馆，BM25 就像通过书名中的关键词查找（精确但僵化），DPR 就像一个理解书籍内容的图书管理员，能够根据你的描述找到相关书籍，即使你用的词和书名完全不同。

DPR 学到的向量空间会将语义相关的问题和段落映射到相近的位置。"谁发明了电话？"和"贝尔获得了电话专利"在这个空间中距离很近，尽管它们共享的词很少。

### 为什么双编码器足够好

双编码器的表达能力理论上弱于交叉编码器（因为问题和段落独立编码，没有交叉注意力）。但 DPR 证明：

1. BERT 预训练已经提供了强大的语言理解能力
2. 对比学习使得向量空间具有良好的区分性
3. In-batch negatives + hard negatives 提供了足够的训练信号

在检索场景中，**速度与精度的权衡**使双编码器成为最实际的选择。

### In-Batch Negatives 的巧妙之处

假设 batch size 为 128，那么每个问题有 127 个"免费"的负例。这些负例是随机的，覆盖了各种主题。模型必须学会将正确的问题-段落对从 128 个候选中挑出来。

随着训练进行，模型学到的向量空间越来越精细，随机负例变得"太容易"。这时困难负例（BM25 检索出的"诱惑项"）变得关键，它们迫使模型关注更细微的语义差异。

## 历史背景

### 发展时间线

| 时间 | 事件 | 关键贡献 |
|------|------|----------|
| 1994 | Okapi BM25 | 经典稀疏检索方法 |
| 2018 | BERT 发布 | 为稠密表示提供了强大的预训练编码器 |
| 2019 | ORQA (Lee et al.) | 首次探索预训练的稠密检索 |
| 2020.04 | DPR (Karpukhin et al.) | 简单高效的稠密检索超越 BM25 |
| 2020.05 | RAG (Lewis et al.) | 将 DPR 与生成模型结合 |
| 2021 | Contriever (Izacard et al.) | 无监督对比学习预训练检索 |
| 2022 | E5, GTR | 更强的通用稠密检索模型 |

### DPR 的历史地位

DPR 是**稠密检索在开放域 QA 上首次大幅超越 BM25** 的工作。虽然之前的 ORQA 也尝试了稠密检索，但效果不如 BM25。DPR 的成功关键在于简单有效的训练策略（in-batch negatives + hard negatives），证明了不需要复杂的预训练流程。

DPR 直接催生了 RAG 等检索增强生成方法，奠定了现代信息检索的稠密表示范式。

## 与其他论文的关联

- **RAG (Lewis et al. 2020)**：DPR 是 RAG 的检索模块，两者形成完整的"检索→生成"管道
- **Attention Is All You Need**：DPR 的编码器基于 Transformer (BERT)，注意力机制是其语义理解的基础
- **Lost in the Middle**：当 DPR 检索出多个段落时，生成模型对不同位置段落的利用程度不同——中间位置的段落容易被忽略
- **Seq2Seq / Pointer Networks**：DPR 可以看作序列到向量的编码问题，与序列到序列框架有联系
